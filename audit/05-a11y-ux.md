### A2. Targets below 44 dp

- **Confirmed:** `lib/features/sheets/sort_filter_sheet.dart:128` — `BoxConstraints(minHeight: 36, minWidth: 36)`
  on a `PulsrPressable` that applies sort direction; effective height = 36 dp (text 14 + 12 padding). **[V]**
- `AppSpacing.minTouchTarget = 48` and `minTouchTargetCompact = 44` exist and are used at call sites, e.g.
  `downloads_screen.dart:201-204`, `advanced_playback_bar.dart:240-241`, `eq_sheet_shell.dart:616-618`. **[V]**
- Sweep for `minWidth/minHeight: 3x` over `lib/features` returned only two hits: the 36 dp above and
  `shortcut_help_sheet.dart:133` (`minWidth: 38`), which is a **non-tappable keycap chip**, not a target. **[V]**
- No other sub-44 interactive target found in the checked patterns. `height: 20–28` hits are skeletons, icons
  and icon circles (e.g. `advanced_playback_bar.dart:249` = 26×26 icon inside a 48 dp `IconButton`). **[V]**
- WCAG 2.5.8 needs 24×24, so 36 dp passes *AA*; it fails the 44/48 dp platform guidance. Low severity.

### A3. Sliders — semantic value

- `semanticFormatterCallback` appears **0 times** in `lib/`. **[V]**
- 19 raw `Slider(` vs 10 `PulsrSlider(` call sites. Raw ones are all in DSP/theme/picker surfaces:
  `eq_advanced_controls.dart:329, 827, 892, 1046, 1109, 1321, 1498, 1673`, `eq_sheet_shell.dart:1569, 2580, 2790, 2952`,
  `custom_theme_builder_screen.dart:520`, `appearance_section.dart:378`, `usb_dac_section.dart:180`,
  `compressor_limiter_sheet.dart:624`, `pulsr_cast_sheet.dart:579, 592`, `quran_mode_sheet.dart:962`, `live_prog_sheet.dart:441`. **[V]**
- Consequence: Flutter's default announces a percentage — an EQ gain of **+6 dB is read as "50 %"**, and
  preamp/delay (ms) the same. `PulsrSlider` has the same limitation: it hard-codes `value: '${(t*100).round()}%'`
  (`pulsr_slider.dart:225`), so dB/ms pickers using it are equally misleading. **[V]**
  Severity: P2 (P1 inside the DSP sheet, which is unusable eyes-free).

### A4. Dynamic type

- Global: `main.dart:1059` wraps the app in `withClampedTextScaling` and the comment states the intent to
  allow the full OS range up to 200 %. **[V]**
- But chrome *does* clamp: `mini_player.dart:779-783` and `1575-1577` (0.8–**1.3**), `bottom_nav_bar.dart:295-297`
  (0.8–**1.4**), `song_tile.dart:285-286` (**1.4**), `tablet_layout_section.dart:48-49` (1.5),
  `responsive_typography.dart:82-110` (`PulsrTextScaleScope`, default 0.85–**1.5**). **[V]**
- At a 200 % OS setting, mini-player title/artist and dock labels render at 130–140 % → **WCAG 1.4.4 fail**
  for the most-used surface. **[V]**
- Fixed-height containers holding text: **no confirmed offender**. The `height: 20–28` hits inspected are
  icon/decoration boxes (`settings_section.dart:47-52`, `advanced_playback_bar.dart:249-251`), not text boxes. **[V]**
  Related risk (unconfirmed): `home_card_metrics.dart:12` clamps derived card text height to `78.0`. **[I]**

### A5. Motion accessibility — WCAG 2.2.2 (Pause, Stop, Hide)

**FAIL.** `lib/core/widgets/marquee_text.dart` starts an unbounded cycle: `_startScrolling` (line 104) →
`Timer(pauseDuration)` → `animateTo(maxScroll)` → `Timer` → `animateTo(0)` → `cycle()` (lines 121-160). It stops
only when the text fits, when `context.motionEnabled` is false, or on dispose. **[V]**

- Only pause affordance is `MouseRegion` hover: `if (widget.pauseOnHover)` at line 238, `MouseRegion` at 239 —
  hover does not exist on touch. **[V]**
- The scroll view is `physics: const NeverScrollableScrollPhysics()` (line 223), so a user cannot even drag it to
  a stop. **[V]**
- No tap-to-pause, no `Semantics` custom action, no stop control, no "reduce motion" per-widget toggle. **[V]**
- Long titles therefore scroll **forever** for touch users with motion enabled → 2.2.2 (moving content that
  starts automatically, lasts >5 s, presented in parallel with other content, no pause/stop/hide). **[V]**
- Same class: `PulsrSlider` runs `_waveController.repeat()` indefinitely when `animateWave` is set
  (`pulsr_slider.dart:92-100`); decorative, but still unbounded auto-motion. **[V]**

### C3. ARB parity + generated output

- All three files are **4,690 lines** (`app_en.arb`, `app_es.arb`, `app_ar.arb`) and sampled keys sit on identical

- A parity test already enforces set equality of non-`@` keys: `test/core/l10n/l10n_test.dart:16-34`
  (`expect(arKeys, equals(enKeys))`, same for ES). **Not executed here** (no shell), but the structural evidence
  (equal line counts, equal key positions) is consistent with it passing. **[V]/[I]**
- Exact key count not machine-enumerated — the match-list tool caps at 100 and the files carry ~1,000 keys each;
  I did not claim a number I could not count.
- `flutter gen-l10n` output **is in sync** for sampled keys: `disconnect` and `clearQueueConfirm` exist in
